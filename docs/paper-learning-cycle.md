# 논문 핵심 학습 흐름 시연

교수자 정책 → 수행 상태에 따른 지원 → 학생의 제안 판단 → 실행 근거 공유 → 조건 변경과 재수행을 연결하는 제한된 데모다. 네트워크 실습과 융합 팀 프로젝트는 같은 화면을 사용하며, 직접 입력한 기록은 **유송민 · 1팀 · 현재 과제**에서 확인. 논문의 교육적 효과를 검증하거나 실제 AI·장비·API를 연결한 구현은 아님.

## 시작과 역할 찾기

1. 저장소에서 `npm ci`, `npm run dev`를 실행하고 `http://localhost:5173`을 연다. 이미 저장한 기록이 있으면 이어서 복원된다. 처음부터 재현하려면 별도의 브라우저 프로필을 사용.
2. 사이드바의 「워크스페이스 전환」에서 「2학년 네트워크 실습」 또는 「융합 팀 프로젝트」를 고른다. 기록은 시나리오별로 분리된다.
3. 「프로필 전환」에서 「강병준 교수자」와 「유송민 학생」을 전환. 태블릿에서는 먼저 「수업 메뉴 열기」를 누른다. 실제 계정 로그인은 아님.
4. 교수자는 「팀별 모니터링」의 「진행 중인 과제」를 현재 과제로 두고 단계 지도의 **1팀** 행을 선택. 다른 팀의 고정 사례와 구분. 평가에서는 「학생별 평가 지원」 → 「학생 검색」에 유송민 입력 → 「학생 선택」에서 「유송민 · 1팀」을 선택.

## 1. 정책을 저장하고 일반 가이던스 받기

교수자 「프로젝트 · 과제 생성」에서 목표를 확인하고 「AI 운영 방식 설정」으로 이동한다. 「교수자 승인형」을 선택하고 「허용 상황 유형」에서 네트워크는 「오류·장애」 또는 「요구사항 변경」, 융합은 「자원 제한」 또는 「역할 변화」를 허용한다. 가이던스 범위와 「개입 수준」을 정하고 「학생 화면 미리보기」 → 「과제 생성」으로 적용. 이미 생성했다면 버튼은 「과제 다시 저장」이다.

**「임시 저장」은 편집 초안만 저장.** 학생에게 적용되는 정책·학습 목표는 「과제 생성」/「과제 다시 저장」 시 갱신된다. 정책을 다시 적용하면 이전 미승인 지원 기록과 대기 중인 변경 상황은 거절 상태로 정리된다. 학생 「개인 AI 지원」의 「현재 수행 맥락」에서 적용 정책을 확인할 수 있다.

| 운영 방식 | 지원 전달 | 다음 상황 적용 |
| --- | --- | --- |
| AI 자동 | 허용 가이던스 안의 작성된 응답을 즉시 전달 | AI가 채팅·기록·학습 증거를 보고 추가 조건을 판단해 바로 적용 |
| 교수자 승인형 | 허용 범위의 가이던스는 승인 없이 즉시 전달 | AI 판단 후 교수자가 승인·적용 |
| 교수자 직접 | 저장된 「가이던스」 문장을 제공 | 학생의 제안 버튼은 비활성; 교수자가 1팀 상세에서 제안하고 승인·적용 |

학생 「개인 AI 지원」에서 「개인 질문」을 입력하고 「AI에게 질문하기」를 누르면 허용된 가이던스가 즉시 제공된다. 「팀 채팅」에서도 프로젝트 방향·구현 방법·조사·검증·역할 분담·갈등 조율을 상의할 수 있다. 「AI 가이던스」를 선택해 요청하면 같은 팀 대화에 답변이 남는다. 일반 지원은 승인 대상이 아님. 교수자 1팀 상세의 「가이던스 제공 현황」에는 지원 주제와 이유가 표시되고 개인 질문 원문은 표시되지 않는다.

지원은 질문 맥락, 최근 실패·부분 확인·검증 공유 상태와 허용된 가이던스 수준을 사용하는 작성된 규칙이다. 실패 시 탐색을 더 돕고, 부분 확인·검증 후에는 판단을 학생에게 돌려주는 방향으로 수준을 고른다. 「최소」 개입은 낮은 수준을 우선하며, 항상 교수자가 허용한 항목 중에서 선택. 허용된 기본 항목이 없으면 지원을 전달하지 않고 교수자 지도 요청을 안내한다. 자유롭게 추가한 항목이 새로운 AI 기능을 생성하지는 않는다. 지원 수준·횟수는 능력 점수가 아님.

## 2. 학생이 제안을 검토하고 선택해서 공유하기

학생 「개인 AI 지원」 아래 「AI 제안에 대한 나의 판단」에서 다음을 수행한다.

1. 「검토할 제안」을 고르고 「나의 판단」을 「채택」·「수정」·「거부」 중 선택.
2. 「채택·수정·거부한 이유」와 「내가 선택한 접근과 확인 방법」을 작성.
3. 아직 실행 전이면 「연결할 검증 근거」를 「아직 검증 전 · 판단과 계획만 공유」로 둔다. 검증 뒤에는 해당 결과를 연결해 새 판단 기록을 공유할 수 있다.
4. 「판단 근거 교수자에게 공유」를 누른다. 선택한 제안·지원 이유와 학생 판단, 선택한 검증 근거가 공유 기록으로 남는다. 개인 대화 전체가 공유되는 것은 아님.

「공유할 지도 요청」 → 「지도 요청 보내기」도 별도의 명시적 공유다. 교수자에게 보내려는 내용만 작성.

## 3. 첫 모의 실행과 원자료 공유

학생 「프로젝트 작업실」 → 「실행 및 검증」을 연다. 조건을 바꾸면 현재 시험 결과가 초기화되므로 **검증 조건을 먼저 선택하고 시험을 실행**한다. 「명령·요청」에 입력하고 「실행」하거나 조회·시험 바로가기를 사용. 네트워크의 완성된 수정 명령은 바로가기로 제공하지 않으며 직접 입력한다.

### 네트워크 실습

「수정 전 실패 결과를 비교 기준으로 사용」과 「반대 방향의 결과까지 확인」을 선택. 「실행 대상」을 바꾸며 아래 순서로 실행한다. 첫 실패와 조회는 이후 설명을 위한 비교 자료다.

| 실행 대상 | 명령·요청 | 확인할 내용 |
| --- | --- | --- |
| PC-A | `ping 192.168.20.10` | 수정 전 실패 |
| R2 | `show ip route` | 잘못된 다음 홉 `10.0.0.9` |
| R2 | `ip route 192.168.10.0 255.255.255.0 10.0.0.1` | 반환 경로 수정 |
| PC-A | `ping 192.168.20.10` | 본사 → 지사 성공 |
| PC-B | `ping 192.168.10.10` | 지사 → 본사 성공 |

### 융합 팀 프로젝트

실습 폼 대신 선택한 도구에서 수행한 자료를 제출한다. 「수행 방법과 도구 선택 이유」, 「산출물·검증 조건·관찰 결과」, 「결과 해석과 목표 충족 설명」을 입력하고 「수행자료 검토 요청」을 누른다. 원본 코드·문서·결과 파일은 「팀 자료」에 첨부한다. 교수자는 1팀 상세의 「수행자료 교수자 확인」에서 원문을 대조하고 「수행자료의 목표 충족 확인」 또는 「추가 수행자료 요청」을 선택. 확인 전에는 첫 검증 완료로 처리하지 않는다.

네트워크는 시험 조건과 결과·판단을 갖춰 「검증 근거 팀에 공유」를 누른다. 두 시나리오 모두 원자료와 학생 설명을 구분하고 이전 기록을 보존. 팀 자료의 조사 노트·인터뷰 CSV·응답계약 JSON·SQL·중간 실행 CSV는 시연용 원본이다. 실제 첨부한 텍스트·코드·CSV는 내용이 바로 표시되고 이미지·PDF는 미리보기 또는 다운로드로 확인할 수 있다.

## 4. 한 번의 추가 상황과 재검증

AI가 새 채팅의 구현 어려움, 공유한 수행 원자료의 실패, 반복 실패 또는 성공·검증 기록을 관찰해 선행 단계나 심화 조건을 판단. 학생에게 상황 선택 메뉴나 제안 버튼은 제공하지 않는다. 자동형은 판단한 조건을 즉시 적용하고 승인형은 교수자 1팀 상세에 승인 요청을 보낸다. 교수자는 AI 판단 이유와 연결된 채팅·학습 증거를 보고 수정·승인 또는 거절한다. 승인 전에는 학생이 기존 과제를 계속 수행한다. 판단은 데모용 상태 규칙이며 실제 AI 모델 호출이 아님. 개인 질문 원문은 판단 근거 카드에도 공개하지 않는다.

| 시나리오 | 지원되는 허용 유형 | 추가 시험 |
| --- | --- | --- |
| 네트워크 | 오류·장애, 요구사항 변경 | R2 뒤의 추가 단말 PC-C `192.168.30.10` 경로 |
| 융합 | 오류·장애·자원 제한(선행), 자원 제한·요구사항 변경·역할 변화(심화) | 외부 API 없이 공개 자료로 필수 안내 유지 |

두 유형을 함께 허용하면 네트워크는 「오류·장애」, 융합은 「자원 제한」을 우선 선택. 허용 유형에 맞는 상황만 자동으로 제안하며 추가 조건을 만들 근거가 없으면 관찰을 계속한다. 교수자의 자유 문장 수정은 안내 내용만 바꾸며 임의의 엔진·장비·시험을 생성하지 않는다.

적용하면 현재 완료 판정·시험·설명이 초기화되고 이전 증거는 유지된다. 학생은 「변경 조건의 영향·대안 비교·팀 역할 합의」를 작성하고 「재분석과 팀 합의 저장」을 누른다. 이 합의는 새 검증 공유의 필수 조건이다.

- **네트워크:** 두 검증 조건을 다시 선택. PC-A에서 `ping 192.168.30.10`의 실패와 R1의 `show ip route`로 추가 경로 부재를 확인. R1에서 `ip route 192.168.30.0 255.255.255.0 10.0.0.2`를 직접 입력한다. PC-A → PC-B, PC-B → PC-A, PC-A → PC-C의 세 ping을 다시 실행한다. 추가 경로 수정도 현재 시험 결과를 지우므로 모든 ping은 수정 후 실행한다.
- **융합:** 외부 API 없이 공개 문서를 조회하는 구현 또는 대안을 팀이 선택한 도구로 수행하고, 변경한 코드·입력별 실행 기록·판단 설명을 새 수행자료로 제출한다. 교수자가 새 범위의 목표 충족을 확인.
- **선행 단계:** 조사 원문과 비교표를 팀 자료에 작성·첨부하고 새 접근의 선택 이유를 합의한다. 선행 단계를 승인했다고 추가 단말이나 외부 API 중단 조건까지 적용되는 것은 아님.

새 설명을 작성하고 「검증 근거 팀에 공유」를 누르면 「재검증 근거 공유됨」으로 바뀐다. **초기 수행 + 추가 상황 1회**만 지원. 완료 후 조건을 바꾸면 같은 추가 회차를 다시 검증해야 하며 기존 증거는 남는다. 세 번째의 새 상황을 생성하는 시연은 제공하지 않는다.

## 5. 다른 접근의 자료 제출과 교수자 확인

정해진 명령 외의 해결 방법은 「실행 및 검증」 하단 「다른 해결 방법으로 수행했나요?」를 펼쳐 제출한다. 외부 원본 파일은 「팀 자료」에 첨부하고 「대안 접근과 선택 이유」, 「외부 원자료·자료명·실행 조건」, 「결과 해석과 목표 충족 설명」을 작성해 「대안 수행자료 검토 요청」을 누른다. 입력한 외부 기록은 학생 제출 자료이며 자동으로 진위를 확인하지 않는다.

교수자 1팀 상세의 「대안 접근 교수자 확인」에서 자료와 목표를 대조한다. 「대안의 추가 자료 요청」을 누르면 학생 화면에도 요청 상태가 표시되고, 학생은 보완 자료를 다시 제출할 수 있다. 「대안의 목표 충족 확인」을 눌러야 완료로 인정된다. 변경 상황 수행 중이라면 먼저 학생의 재분석·팀 합의가 필요하다. 재제출도 앞선 증거를 보존하며 교수자는 최신 요청을 검토한다.

## 6. 증거 대조와 평가 경계

교수자 「학생별 평가 지원」에서 유송민을 선택해 「과정증거」와 「가이던스 이력」을 확인. 원자료, 학생 설명, 잠정 AI 해석, 교수자 확인을 구분. 학생이 공유한 제안 판단은 해당 지원 사건과 연결되고, 실행 결과는 저장된 증거 ID를 유지. 수행 보드의 자기 설명이나 상황 대응 계획은 실제 실행 결과로 표시하지 않는다.

직접 입력한 새 기록은 내용 검토 전 고정 비율의 수치 점수를 만들지 않는다. 기존 가상 학생 사례의 숫자는 시연 예시로 남는다. 교수자가 증거 확인·평가 판단·피드백을 별도로 저장하며 유송민의 저장된 피드백은 학생 학습 기록에 나타난다.

## 저장·개인정보·시각 경계

- 브라우저 로컬 저장만 사용. 네트워크는 `trace-project-network-v2`, 융합은 `trace-project-fusion-v2`이며 적용 과제 정책, 가이던스 제공 기록, 상황, 모의 실행 상태, 공유 근거와 대안 검토 상태를 포함. 실제 서버·인증·계정 권한·다중 사용자 동기화는 없다.
- 개인 대화 원문은 교수자 화면에 표시하지 않는다. 교수자는 제공된 가이던스와 수행 상태 요약, 명시적으로 공유한 지도 요청·제안 판단·수행 근거를 본다. 개인 대화도 같은 브라우저 저장소 안에 있으므로 이는 화면·데이터 연결 수준의 분리다.
- 원자료는 시연용 조사 문서·코드·중간 로그 또는 학생이 첨부·입력한 자료다. 실제 장비·코드·API의 실행, 자동 채점, 이해도 진단이나 외부 자료의 진위 보증을 해당 없음.
- 기존 녹색 내비게이션, 흰 작업 패널, 의미별 표면, 입력·버튼·접기 요소를 확장한다. 제안 판단은 개인 지원 아래, 승인·상황·대안 검토는 1팀 상세, 현재 상황은 작업실 탭 위에 둔다. 추가된 두 열 입력은 좁은 화면에서 한 열로 쌓인다. 새로운 디자인 토큰·이미지·자산은 추가하지 않는다.
