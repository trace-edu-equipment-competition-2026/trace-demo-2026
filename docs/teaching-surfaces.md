# TRACE 교수자 운영 화면

## 역할과 방향

기존 TRACE 색상, 사이드바, 흰 카드, 입력폼, 버튼을 재사용하는 Operate 화면이다. 팀별 모니터링은 개입할 팀과 확인 이유를 찾고, 학생별 평가 지원은 학습 목표에 연결된 수행자료를 대조하여 교수자가 판단하도록 돕는다. 새로운 시각 시스템을 만들지 않으며 `DESIGN.md`와 `.impeccable/design.json`은 유지한다.

평가 지원의 연구 근거, 원문 확인 범위, 설계 해석과 과목 확장 제안은 [평가 지원 개편의 근거와 실습 확장안](evidence-design-rationale.md)에 기록한다. 이 화면이나 가상 AI 해석의 교육적 효과가 검증되었다는 뜻은 아니다.

## 역할별 공통 화면 계약

네트워크 실습과 융합 팀 프로젝트는 `scenarios.ts`가 선택하는 데이터 변형이다. 공통 `WorkspaceSidebar`와 교수자 메뉴를 사용하고, `TeachingWorkspace`·`EvidenceReview`의 전체 모니터링·평가 화면을 그대로 공유한다. 카드, 필터, 증거 탐색기, 가이던스 차트, 평가 입력폼을 시나리오별로 따로 만들지 않는다. `CourseDashboard`·`CourseSettings`와 세 단계 과제 생성도 같은 원칙을 따른다. 별도 `FusionWorkspace.tsx`는 제거했다.

`KnowledgeConnections`는 두 시나리오 모두에서 이전 학기·이번 학기·다른 교과·새 학습의 연결과 적용 계획을 보여 준다. 팀 상세와 학생 평가에 같은 컴포넌트를 사용하며, 과제 설계와 학생 계획/학습 기록의 공통 폼에서 연결을 추가한다.

## 팀 모니터링과 공통 시나리오

두 시나리오는 모두 24명·6팀의 가상 수업을 사용한다. 아래 팀 상태 표와 네트워크 명칭은 네트워크 데이터의 예시다. 융합 데이터는 같은 화면에 캠퍼스 길잡이·공유물품 연결소·학습 회고 노트·급식 수요 예측·접근성 안내 도우미·에너지 사용 리포트의 요구, 지식, 도구, 검증 맥락을 넣는다. 팀 단계 지도는 현상 확인 → 원인 분석 → 설정 수정 → 결과 검증을 행별로 보여 주며, 팀을 선택하면 확인 이유, 팀원 역할, 주요 이벤트와 운영 액션이 바뀐다. 단계 분포는 각 단계에 있는 팀 수를 나타내며 진행률과 함께 능력·이해도·평가 점수로 사용하지 않는다.

팀 현황과 학생 근거는 `src/scenarios.ts`의 팀 데이터와 `scenarioEvidence`를 사용하며 기존 `src/evidence.ts`의 공통 증거 구조를 유지한다. 유송민은 해당 워크스페이스에 저장한 개인 수행 근거·명시적 지도 요청·가이던스 요약을 평가에 연결한다. 나머지 학생은 작성된 예시 자료를 사용한다. 아래 E01–E05의 구체적인 내용은 시드 예시이며 실제 저장된 학생 근거에 따라 목록이 달라진다. 수업 현황은 14:31 기준이며, 팀의 최근 활동과 학생의 마지막 증거 시각을 맞춘다. 팀 이벤트의 14:31 항목은 시스템의 현황 확인이고 새로운 학생 수행이 아니다.

| 1팀 | 결과 검증 | 14:26 · 5분 전 | 두 단말 양방향 결과 수집, 다른 단말로 검증 범위 확장 |

과제 선택, 상태 필터, 팀 선택, 승인·수정 후 승인·거절, 가이던스 제안 작성이 동작한다. 승인한 수정 상황은 해당 팀 상세에 표시된다. 팀원 이름 또는 팀 상세의 평가 근거 버튼은 해당 학생 평가로, 학생의 팀 보기 버튼은 같은 팀 모니터링으로 이동한다. VLAN 예시 과제에서는 VLAN 구성·통신 검증으로 명칭과 원자료가 바뀌며 미수집 단계와 팀별 시간은 같은 시나리오를 따른다.

## 학생별 평가 지원

학생 검색 옆의 학생 선택 드롭다운으로 대상 학생을 바꾸며, 이름 또는 팀 검색이 드롭다운 목록을 좁힌다. 검색 결과가 없으면 이를 옵션으로 표시하며 기존 학생의 검토 내용은 유지한다. 별도 학생 목록 사이드 패널 없이 평가 영역이 본문 전체 폭을 사용한다.

첫 요약에는 팀 과제 진행률 원형 차트, 판단·근거·수정·검증별 실제 증거 수 막대 차트, 교수자 확인 완료 비율 원형 차트를 배치한다. 확인 비율의 중앙 숫자는 완료 수/전체 증거 수이며 0건은 빈 원으로 표시한다. 근거 확인은 입력 상태를 즉시 반영하고 저장 이후 새로고침에도 유지된다. 단계별 막대를 누르면 해당 증거를 연다. 팀 진행률은 학생 능력 점수가 아니다. 이어서 강점과 다음 확인 질문을 나란히 제시한다. 2·6팀은 검증 결과 부재, 4팀은 수정안 선택과 수정·검증 자료 부재, 검증 기록이 있는 팀은 검증 범위의 한계를 명시한다.

강점·보완점, 학습 상태, 교과 개념별 확인 포인트, 역할에 따른 실제 행동, 평가 기준의 참고 자료는 모두 E01–E05 중 실제 존재하는 가상 증거를 연다. 증거 바로가기는 단계 필터를 해제하고 해당 상세로 이동한다. 검증 계획을 실제 검증 결과로 표시하지 않으며, 팀 자료를 해석한 행동과 직접 명령을 실행한 행동도 구분한다.

### Learning Evidence 탐색기

전체 또는 판단·근거·수정·검증 필터로 증거 목록을 좁히고, 선택한 자료를 네 층으로 대조한다.

- **원자료:** 명령 출력, 설정 변경 전후, 계획·자기 설명 기록. 출처, 시각, 학습 목표, 개인/팀 공유 여부와 시연용 표시를 제공한다.
- **학생 설명:** 해당 학생이 작성한 판단 근거와 후속 계획을 보여 준다.
- **AI 해석:** 자료에서 관찰한 내용을 잠정적으로 정리하고, 이해 확정·검증 범위·직접 수행 여부의 한계를 함께 밝힌다.
- **교수자 확인:** 미확인 / 확인 완료 / 추가 확인 / 해석 수정 필요와 메모를 입력하고 확인 저장으로 남긴다.

자료가 없는 단계는 빈 상태와 다음 계획으로 가는 링크를 제공한다. 4팀은 E03·E04가 없고 E05가 진단 계획이며, 2·6팀은 E04가 없고 E05가 검증 계획이다. 원자료가 없다는 이유만으로 이해 부족이나 미참여를 확정하지 않는다.

### L1–L4 가이던스 흐름

계단 차트는 L1 확인 질문, L2 탐색 범위, L3 개념 힌트, L4 도구 활용 힌트를 표현한다. 각 수준의 배경·선·범례는 민트·라벤더·노랑·코럴로 구분한다. 오른쪽 누적 막대와 수준별 가로 막대는 전체 지원 횟수를 분모로 사용하며 횟수와 비중을 함께 표시한다. 사건 버튼을 선택하면 지원 이유 → 지원 내용 → 후속 학생 행동과 연결 증거가 바뀐다. 시연에는 L1→L2→L3→L4→L1과 L1→L2→L1의 경로가 있으며, 4팀의 후속 행동은 진단 계획에 머문다.

가로 간격은 사건 순서에 따른 배치로 실제 경과 시간에 비례하지 않는다. 수준·횟수는 지원 기록이며 학생 능력이나 효율 점수가 아니다. 개인 AI 채팅 원문은 공개하지 않고 지원 요약과 관찰된 후속 행동을 제공한다. 직접 답안 제공이나 실제 AI 호출은 없다.

### 교수자 평가와 저장

현재 과제의 제목·운영 방식·평가 기준은 생성하여 적용한 과제 상태를 사용한다. 「임시 저장」의 편집 초안은 학생 정책을 바꾸지 않는다. 기준별 AI 추정 충족분을 배점과 함께 표시한다(18/20점, 24/30점). 모든 행은 최대 배점을 공통 눈금으로 사용한다. 배점 20의 옅은 막대는 배점 30보다 짧고, 18점 색 막대는 같은 눈금의 18에서 끝난다. 각 행을 같은 길이로 정규화하거나 90%로 바꾸지 않는다.

기존 고정 사례의 값은 `criterionEstimate`의 시연 예시이며 실제 AI 채점이나 검증된 평가 모형이 아니다. 유송민이 직접 저장한 새 기록은 내용 검토 전 수치 점수를 추정하지 않고 교수자 판단을 기다린다. 검증 결과가 없거나 사용자 정의 기준에 대응하는 근거가 없으면 0점 대신 산정 대기로 표시한다. 추정 이유와 근거를 열어 검토하고 교수자가 판단과 피드백을 직접 입력한다. 판단은 선택되지 않은 상태로 시작하며 AI가 성적을 확정하지 않는다. 증거별 교수자 확인과 과제 평가 판단은 별도 기록이다.

학습 상태 바로가기는 진한 색 면·원형 아이콘·화살표를 사용하는 레퍼런스 카드로 구성한다. 교과 개념과 역할 수행은 헤더·얇은 구분선·상태 텍스트의 간결한 표로 배치한다. 데스크톱에서 두 표를 나란히, 1250px 이하에서 세로로 배치한다.

- **증거 확인:** 과제·학생·증거 키로 상태와 메모를 `workspaceKey(id, 'trace-evidence-checks')`에 저장한다. 확인 저장 후 해당 증거 ID를 포함한 알림이 표시되며 새로고침 후 복원된다.
- **학생 평가:** 과제·학생 키로 판단과 피드백을 `workspaceKey(id, 'trace-reviews')`에 저장하고 처리 알림을 표시한다. 유송민의 저장된 피드백은 같은 시나리오 학생 학습 기록에도 연결한다.
- **승인·가이던스:** 기존 고정 팀 사례의 승인은 화면 세션의 시연 상태다. 현재 과제 1팀의 일반 지원 제공·추가 문제 상황 승인·대안 자료 확인은 프로젝트 로컬 기록에 저장된다. 1팀 가이던스 제안을 저장하면 같은 시나리오 프로젝트 기록의 교수자 답변으로 반영하여 학생 대시보드·지원·학습 기록에 표시한다. 외부 메시지 전송은 없다.

`workspaceKey`는 네트워크의 기존 키를 유지하고 융합에는 `fusion-` 접두사를 붙인다. 공통 학생 프로젝트 기록은 `trace-project-network-v2`와 `trace-project-fusion-v2`로 분리한다. 개인 대화 원문은 교사용 화면에서 읽어 표시하지 않으며 명시적 지도 요청과 수준·목적·시간 요약만 연결한다.

브라우저 로컬 저장이며 계정 간 동기화나 서버 영구 저장은 아니다. 증거 확인과 평가의 입력 변경은 화면에 즉시 보이지만 새로고침 후 보존하려면 각각 저장해야 한다.

## 수행 환경 선택과 학생 미리보기

과제 생성의 수행 환경에서 프로젝트 작업공간 / 연결된 실습 모듈 / 외부 도구·현장 실습을 선택한다. 설정은 과제의 임시 저장·생성에 포함되며 학생 미리보기에 반영된다.

| 선택 | 구현된 UI | 현재 한계 |
| --- | --- | --- |
| 프로젝트 작업공간 | 문서·토론·산출물 중심 수행 안내 | 학생 공통 작업실과 팀 자료에서 로컬 문서 편집·공유를 제공하나 서버 협업이나 자동 수집은 없음 |
| 연결된 실습 모듈 | 정적 라우팅 장애 진단 또는 VLAN 소속 오류 진단 선택, 학생 미리보기에서 토폴로지·문제 상황·명령 출력 예시 열기 | 미리보기는 예시이며 학생 공통 작업실은 정의된 명령·요청만 처리하는 모의 실행을 제공. 실제 장비·코드·API 실행은 없음 |
| 외부 도구·현장 실습 | 선택 주소·실습 안내 입력, 학생 미리보기에서 안내 및 HTTP(S) 도구 링크 열기 | 외부 활동 자동 수집은 없음. 학생 작업실에서 외부 원자료·자료명·조건·설명을 명시적으로 제출하고 교수자 확인을 요청할 수 있음 |

공통 학습 과정은 판단 → 실행·수정 → 검증 → Learning Evidence로 안내한다. 과목별 실제 연결은 모듈이 관찰할 수 있는 사건과 검증 조건을 먼저 정해야 한다. 현재 모니터링·평가는 가상 수업 시나리오를 사용하고 유송민의 로컬 저장 근거·지원 요약을 연결한다. 과제 생성이나 환경 선택만으로 새 학습 로그가 생기지는 않으며 학생이 계획·수행·검증을 명시적으로 저장해야 기록된다.

## 데스크톱·태블릿 UX와 시각 시스템

짙은 녹색 내비게이션, 회백색 배경, 흰 패널과 기존 민트·노랑·장미·라벤더 상태색을 유지한다. 색은 상태 문자와 함께 표시하며 별도의 브랜드 토큰을 추가하지 않는다. 기존 `DESIGN.md`의 과제 생성 2열 구성은 해당 화면의 기록이며 운영 화면에 강제하지 않는다.

데스크톱 모니터링은 팀 지도와 선택 상세를 약 62:38로 배치하고 900px 이하에서는 순서대로 쌓는다. 평가 화면은 전체 폭을 사용한다. 과제 선택·학생 검색·학생 선택을 상단에 모으며, 태블릿에서는 과제 선택 아래에 검색과 드롭다운을 나란히 배치한다. 600px 이하에서는 입력 컨트롤을 세로로 쌓는다. 팀 지도 각 행, 평균 진행률, 선택 팀 상세의 퍼센트도 원형 차트로 표시한다.

900px 이하에서는 증거 목록이 상세 위로 이동하고 지원 이유·후속 행동을 세로로 배치한다. 가이던스 흐름과 사용 비중은 태블릿까지 나란히 유지하며 600px 이하에서 세로로 배치한다. 강점·확인 질문도 600px 이하에서 세로로 배치한다. 과제 수행 환경 선택은 700px 이하에서 한 열이 된다. 1050px 이하의 사이드바는 기존 서랍형 내비게이션을 사용한다. 좁은 화면의 단계 지도·평가 표는 내부 스크롤로 열 관계를 보존한다.

단계·필터·증거·지원 사건은 클릭 가능한 버튼이고, 필터·증거·지원 사건의 선택 상태는 `aria-pressed`로 제공한다. 증거 바로가기는 상세 제목으로 키보드 초점을 옮긴다. 가이던스 차트에는 사건 요약 대체 텍스트가 있으며 전역 키보드 포커스와 reduced-motion 설정을 유지한다.

## 확인 범위

`tests/teaching.spec.ts`는 승인 수정 → 학생 평가 이동 → 저장 → 학생 전환 → 새로고침 복원과 1440/1180/820/390 폭의 레이아웃을 다룬다. `tests/evidence.spec.ts`는 팀·학생의 시간·검증 상태 일치, 원자료 대조와 증거 확인 저장, 지원 이후 행동, 수행 환경 선택·미리보기·저장을 다룬다. 기존 과제 생성 시나리오는 `tests/assignment.spec.ts`에 유지한다.

시각 검토는 1440/1180/820/390px 폭에서 진행한다. 학생 검색의 빈 상태·선택 후 기록 분리, 팀 진행률 차트, 기존 평가 저장과 실습 미리보기를 테스트로 확인한다. 과제 생성의 비활성 「정답 직접 제공」 옵션은 제거했다.

## 논문 학습 흐름 보완 · 현재 과제 1팀

「팀별 모니터링」에서 현재 과제의 1팀 행을 선택하면 「가이던스 제공 현황」, 「추가 문제 상황 승인」, 제출된 경우 「대안 접근 교수자 확인」을 확인한다. 일반 질문·프로젝트 논의·역할 분담 가이던스는 바로 제공된다. 선행 단계·심화 조건을 추가하는 문제 상황만 원래 과제·추가 조건·제안 이유·원자료를 대조해 승인 또는 거절한다. 개인 질문 원문은 표시하지 않는다.

상황 변경은 첫 검증 이후 지원되는 허용 유형에 한정하며 초기 수행 뒤 한 번의 추가 회차만 제공한다. 교수자는 안내를 수정할 수 있지만 자유 문장으로 임의의 시험을 생성하지 않는다. 학생의 재분석·팀 합의와 새 시험이 필요하며 이전 원자료는 남는다. 외부 대안은 「대안의 목표 충족 확인」 또는 「대안의 추가 자료 요청」으로 검토한다. 추가 자료 요청과 목표 충족 확인은 학생 작업실에도 표시된다.

평가 대상은 「학생 검색」과 「학생 선택」에서 유송민 · 1팀을 선택한다. 새 원자료·학생 설명·공유한 제안 판단은 저장된 ID와 학습 목표로 연결하며 기존 고정 점수 사례와 구분한다. 정책 저장, 두 시나리오의 명령, 채택·수정·거부 공유와 개인정보 경계는 [논문 핵심 학습 흐름 시연](paper-learning-cycle.md)을 따른다.
