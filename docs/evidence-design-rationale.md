# TRACE 평가 지원 개편의 근거와 실습 확장안

2026-09-25. 첨부 논문 최종본 2쪽, 발표자료 초안 23슬라이드와 원문/공개 초록을 대조. 이 문서는 연구의 주장, 이번 UI의 설계 해석, 아직 구현·검증하지 않은 범위를 구분. 모든 학생·수행 기록은 시연용이다.

## 1. 무엇을 평가 지원으로 볼 것인가

첨부 논문 Ⅱ-3(2쪽)은 학습 증거를 학생 설명, 실행 이력, 산출물, 검증 결과 등 **학습 목표와 연결하여 확인할 수 있는 수행자료**로 정의. 목적은 모든 활동의 수집이나 활동량 점수화가 아님. 학생이 무엇을 근거로 판단했고, 결과에 따라 어떻게 수정했으며, 무엇을 검증했는지 확인하는 것이다.

이 정의에 따라 기존의 ‘충분/부족’ 요약만 있는 화면을 다음 구조로 변경.

| 교수자의 질문 | 화면 | 확인할 수 있는 자료 |
| --- | --- | --- |
| 지금 어느 단계인가? | 판단 → 근거 → 수정 → 검증의 클릭 가능한 과정도 | 단계에 연결된 증거 목록, 미수집 표시 |
| 잘한 점과 확인할 점은 무엇인가? | 강점 / 다음 확인 질문 | E01–E05 증거로 이동 |
| 무엇을 실제로 했는가? | 역할에 따른 행동, 교과 개념별 확인 포인트 | 학생 작성 기록과 팀 공유 자료의 구분 |
| AI 해석이 맞는가? | 원자료 / 학생 설명 / AI 해석 / 교수자 확인 | 라우팅 출력, 설정 변경, 학생 설명, 해석의 한계 |
| 어떤 지원을 받고 어떻게 반응했는가? | L1–L4 계단 차트와 이벤트 선택 | 지원 이유 → 지원 내용 요약 → 후속 학생 행동 → 증거 |
| 무엇을 피드백할 것인가? | 과제 평가 기준, 근거 링크, 교수자 판단·피드백 | 미확인 상태에서 시작, 교수자가 저장 |

교수자 확인은 자료에 대한 검토이며 학생의 성적 확정과 별개. 근거가 없으면 ‘추가 확인’이지 ‘능력이 부족함’이 아님. 팀 자료를 보고 설명한 학생과 직접 명령을 실행한 학생도 구분.

## 2. L1–L4의 정확한 의미

사용자가 ‘럼바우 레벨’이라고 표현한 항목은 확인 결과 발표자료 11쪽의 **가이던스 수준**이다.

| 수준 | 의미 | UI 시나리오의 요약 |
| --- | --- | --- |
| L1 | 확인 질문 | 어디까지 확인했는지 설명하기 |
| L2 | 탐색 범위 제시 | 한 방향뿐 아니라 반환 경로 비교하기 |
| L3 | 개념 힌트 | 요청과 응답이 모두 도달해야 한다는 원리 떠올리기 |
| L4 | 도구 활용 힌트 | ping·tracert 결과를 비교하는 방법 살피기 |

L4는 학생의 수준이 높거나 낮음을 의미하지 않는다. 차트는 시간에 따른 **제공된 지원**을 표시. 막히면 지원을 늘리고 스스로 진행하면 다시 줄이는 모습을 표시. 이번 시연에는 L1→L2→L3→L4→L1과 L1→L2→L1의 두 경로가 있다. 직접 답안 제공은 없다. 개인 채팅 원문은 교수자에게 노출하지 않고 지원 요약과 관찰된 후속 행동만 제공.

발표자료 12쪽의 ‘보완형/기본/도전형 상황’은 별도의 적응 축이다. 이를 L1–L4나 교수자 승인 여부와 같은 지표로 합치지 않는다. 이번 보드의 승인은 상황 제안을 검토하는 기존 흐름을 유지.

## 4. 시각화의 의미와 한계

- 팀 단계 지도: 행=팀, 열=수행 단계. 색과 문자를 함께 사용해 진행·확인·지연·승인을 구분. 팀 선택으로 우측 운영 상세가 바뀐다.
- 단계 분포: 각 단계에 있는 팀 수를 전체 팀 수에 비례해 그린다. 능력 평균을 해당 없음.
- 학생 과정도: 해당 단계의 증거 수와 미수집을 표시. 클릭해 자료를 살핀다.
- 교과 개념: 비교·설명 자료의 존재와 추가 확인 질문을 표시. 정밀 측정되지 않은 이해도 퍼센트나 임의의 레이더 점수를 만들지 않는다.
- L1–L4: 시각적으로 간격을 나눠 사건 순서를 표현한다. 시간의 연속 측정치나 효율 점수가 아님. 빈도를 잘함/못함으로 환산하지 않는다.
- 강점·보완점: 샘플 근거에 대한 잠정적인 해석이다. 검증 계획만 제출된 학생에게 실제 검증을 수행했다고 표시하지 않는다.

## 5. 과목 확장: 공통 학습 구조 + 과목별 실행 모듈

모든 과목을 하나의 실습 폼으로 만들면 개별 도구의 상호작용과 검증 방법을 끝없이 구현해야 한다. 대신 과제 설계와 증거 검토는 공통으로 두고 실행 환경만 교체한다. 이는 첨부 논문 Ⅱ-2와 발표자료 19–20쪽의 두 트랙·확장 구조를 구현하기 위한 제안이다.

| 수행 환경 | 학생이 하는 일 | 수집 가능한 증거 | 이번 데모 범위 |
| --- | --- | --- | --- |
| 프로젝트 작업공간 | 문서, 토론, 산출물 작성 | 문서 수정, 판단 설명, 공유 기록, 산출물 | 환경 선택과 학생 안내 |
| 연결된 실습 모듈 | 네트워크·코딩·장비 시뮬레이터 실행 | 모듈이 제공하는 명령·설정·검증 이벤트 | 네트워크 템플릿 선택, 정적 토폴로지·명령 결과 미리보기 |
| 외부 도구·현장 실습 | 외부 프로그램이나 실제 장비 사용 | 학생 제출 파일·설명, 연동된 경우에만 자동 기록 | 주소·안내 입력과 미리보기. 자동 수집 한계 명시 |

### 추후 실제 연결 시 공통 계약

공통 이벤트에는 과제/활동 ID, 학생/팀 ID, 발생시각, 출처, 학습 단계, 자료 식별자, 목표, 학생 설명, 연결된 가이던스, 검증 결과를 포함. 원자료는 수정 이력과 함께 보존하고 AI 해석 및 교수자 확인과 별도로 저장. 팀 공통 자료에는 작성자·실행자·해석자를 구분.

각 모듈은 **무엇을 관찰할 수 있는지**를 먼저 선언해야 한다. 네트워크는 명령과 통신 결과, 과학은 측정값과 실험 조건, 글쓰기는 초안 변경과 근거, 설계는 버전과 테스트 결과 등이다. 공통 보드는 이를 판단–실행/수정–검증으로 연결하지만, 과목 고유의 성공 조건을 임의로 같게 만들지 않는다.

자동 수집되지 않는 도구에는 업로드·학생 설명 경로를 기록. ‘로그가 없음’을 ‘미참여’로 해석하지 않는다. 연동 모듈의 기록과 학생 제출 자료는 출처가 달라야 한다. 실제 연결에서는 식별자·접근 권한·이벤트 중복·지연 수집·시간 순서·보존 정책도 함께 설계해야 한다.

### 권장 구현 순서

1. 네트워크 모듈 하나에서 진단 → 수정 → 검증 → 증거 검토가 끝까지 연결되는지 검증.
2. 팀 문서/산출물 프로젝트로 같은 보드가 다른 종류의 자료를 처리하는지 확인.
3. 외부 도구 링크·제출 경로 제공 후, 수요가 검증된 도구만 연결 모듈 추가.
4. 과학·수학·AR/XR은 관찰 가능한 수행 이벤트와 검증 조건을 정한 후 확장.

현재는 UI 데모로 실제 AI, 실습 엔진, 외부 수집 API, 자동 검증 엔진은 연결하지 않았다. 환경 선택은 저장되며 학생 미리보기에 반영된다. 모니터링·평가 기록은 별도의 가상 수업 시나리오이고, 과제 생성 결과에서 새 학습 로그가 생성되는 것은 아님.

## 6. 시연 순서

1. 팀별 모니터링의 2팀을 선택해 수정 후 검증 결과가 없는 이유를 확인. 팀과 학생 화면은 같은 팀별 시나리오·시간·검증 결과를 참조한다.
2. 이서연의 평가 근거로 이동해 강점과 검증 결과 미수집을 비교한다.
3. E02 원자료와 학생 설명을 대조하고 교수자 확인을 기록.
4. 검증 단계 필터로 들어가 결과가 없음을 확인하고 E05의 계획을 연다.
5. L4 지원을 선택해 도구 활용 힌트 뒤 계획은 작성했지만 결과는 아직 없다는 점을 확인.
6. 김민준으로 전환해 양방향 검증 기록과 지원이 L1로 줄어든 경로를 비교한다.
7. 평가 기준의 근거 링크를 검토한 뒤 교수자 판단과 피드백을 저장.
8. 과제 생성에서 수행 환경을 실습 모듈로 선택하고 학생 미리보기의 환경 구성을 확인.

## 평가 요소별 충족분 시연 보완

사용자가 요청한 배점 기반 추정 시각화를 추가했다. 18/20점처럼 현재 충족분과 배점을 표시하고 같은 점수 눈금을 사용. 옅은 영역의 끝은 각 배점, 색 영역의 끝은 충족분이다. 20점과 30점 막대의 길이를 같게 정규화하지 않는다.

수치는 현재 시연 시나리오의 고정 예시이며, 위 참고문헌이나 논문이 해당 수치·계산법의 타당성을 입증한다는 뜻이 아님. 실제 적용에는 과목별 세부 루브릭, 근거 연결, 교수자 검토와 평가 타당성 검증이 필요하다. 검증 결과 미수집과 미지원 사용자 정의 요소에는 임의 점수를 생성하지 않는다. 최종 판단 입력과 저장은 교수자에게 남겨 두었다.
